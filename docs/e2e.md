# 端到端验收

`tools/e2e.mjs` 是计划里那条验收标准的可执行版本：它**通过插件自己的工具定义**驱动一个
真实运行的 Gandi，而不是绕过工具层去调底层函数。所以任何一层的回归都会在这里露出来
——参数校验、错误翻译、桥接服务与租约、编译器、引擎形态转换、资产安装、序列化。

## 怎么跑

```powershell
# 1. 先把 Gandi 带调试端口启动起来（没启动也行：e2e 自己会开一个编辑器页签）
Start-Process 'E:\Gandi\Gandi.exe' -ArgumentList '--remote-debugging-port=9222'

# 2. 跑验收
cd E:\dsh-gandi
node tools/e2e.mjs              # 结束时还原用户原本打开的项目
node tools/e2e.mjs --keep       # 保留改动，自己看效果
node tools/e2e.mjs --port 9333  # 换端口
```

脚本会先快照**它自己那个页签**里打开的项目，最后原样还回去；产物写在 `.e2e/` 下。

## 覆盖范围（当前 67 项断言）

| 阶段 | 断言的内容 |
| --- | --- |
| 状态 | 调试端口开着；能挂接上；能列出打开的项目的角色与脚本数 |
| 编译 | `dryRun` 在**不碰编辑器**的前提下编译成功且零告警 |
| 写入 | 就地应用 8 个引擎块；旧脚本被替换；XML 里声明的变量被创建 |
| 读取 | `gandi_inspect` 能看到新脚本的 opcode，并打印出 XML |
| 运行 | 跑 1 秒后精灵精确落在 (120, −60)、变量等于写入的 7；截图是合法 PNG |
| 观察 | `gandi_observe` 与 `gandi_run` 的结论一致 |
| 美术 | 自绘 SVG 造型被装进角色并成为当前造型；旋转中心由 SVG 尺寸推出 (20, 20) |
| 角色 | 复制角色（连造型）、重命名、摆位置/大小、再删除 |
| 导出 | `.sb3` 落盘；重新解析后脚本、变量都在；**资产引用与归档内容完全一致（零告警）** |
| 离线读 | **编辑器导出的那个真实归档**能被 `gandi_inspect {path}` 读出脚本与造型 |
| 回读 | 导出的文件能被重新打开，积木数一致 |
| 输入 | 松开按键精灵不动；**在跑的过程中**按下空格键则移动；能停下所有脚本 |
| 背景 | 给舞台加背景，`gandi_inspect` 能看到它 |
| 位图 | 自造一张 12×12 PNG 作为造型装进角色 —— 覆盖 `AssetType.ImageBitmap` 那条路 |
| 变量 | 建 / 设值 / 建列表 / 重命名 / 删除；删掉一个之后另一个仍在 |

| 新项目 | `gandi_new` 给的项目里起始角色真实存在、零脚本、一个造型 |

取决于上一次运行留下了什么。）

## 为什么这些断言值得存在

有几条是踩过坑之后补上的，它们各自守着一个**在编辑器里看不出来**的失败模式：

- **截图必须是合法 PNG**：`requestSnapshot` 的回调在窗口不在前台时不会触发，
  表现为超时而不是坏图；反过来，如果拿到了 data URI 却不校验字节，
  一张空白图也会被当成成功。
- **导出后要重新解析并做引用一致性检查**：造型资产曾经被打进归档却没有被项目引用，
  而编辑器里造型显示完全正常（见 `docs/spike.md` 的发现 A）。
  只看"文件生成成功"是查不出来的。
- **跑完要断言坐标与变量值**：积木图形状正确、能装载、能渲染，但**语义**可能是错的
  ——输入名写错时积木照样显示，只是不生效。
- **按键要按在"跑的过程中"**：这一条在 Gandi 上是硬性的。`runtime.greenFlag()` 会
  `stopAll()` 并清空按键缓存，而 `当按下…键` 又是由 KEY_PRESSED 事件驱动的（不是每帧轮询），
  所以"先按键、再点绿旗"这种写法**永远是绿的**——它什么都没测。断言里用的
  `gandi_run {input:[{key:'space'}]}` 才是真的按下去（见 `docs/gandi-spike.md` 第 10 条）。
- **导出后要挑对目标**：这一条是被真机打回来才补的。运行到后半段会新建角色，
  于是"第一个角色"已经**不是**被写脚本的那个了，断言却还在看它，
  结果报"导出的项目里没有脚本"——而项目里明明有。现在从 apply 的报告里读出目标名。

## 前提与限制

- 需要一台正在运行的 Gandi（`--remote-debugging-port`）和一个登录过的账号。
  每次运行都会**新开一个编辑器页签**，所以上一轮的残骸不会变成这一轮的"原始项目"——
  也因此不需要先跑 `cleanup-editor --reset`。
- 脚本用一个假 cordis ctx 注册工具，因此**没有** `attachments` 服务：
  截图会走"写 PNG 文件并报路径"的降级路径，这本身也是被断言的一部分。
  在真实 DSH 会话里装了附件服务时，同一个工具会返回图片块。
- 会把编辑器里的项目改掉，所以务必让脚本跑完（它自己负责还原）；
  中途 Ctrl-C 会留下改动，用 `--keep` 反过来可以故意保留。
